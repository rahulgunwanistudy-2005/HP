# Persistent authoring API

All paths below start with `/api/authoring`. Validation failures are HTTP400 `{error:{code,message,details?}}`, missing records HTTP404 and conflicting duplicates HTTP409. POST creates a stable generated id and returns HTTP201 with the created record; PATCH returns HTTP200 with the saved record. Opportunity returns include computed score, linked documents, buyers, actions and notes. Changes, prior state and score snapshots commit atomically. Authored and edited records are retained during reviewed-seed synchronization.

- POST `/accounts`: `{name,domain,industry,summary,hqCountry?,purchasingCountry?,legalEntity?,purchasingOrganization?,registryId?,parentName?,contractingEntity?,discovery?,rationale?,screeningStatus?,hqCity?,hqSubregion?,hqSubregionCode?,purchasingCity?,purchasingSubregion?,purchasingSubregionCode?}`. Domain is a hostname without scheme/path. New accounts start `needs_review`; retrieve sources for that account before factual acceptance.
- PATCH `/accounts/:id`: any nonempty subset of the above, plus `{reviewStatus?,evidenceIds?}`. Country fields accept an uppercase ISO3166 country code or null. Locality fields accept text or null. Reviewed acceptance requires same-account reviewed evidence. Location changes return to `needs_review` unless the edit explicitly includes reviewed acceptance and its evidence.
- POST `/facilities`: `{accountId,name,country,city?,address?,kind?,role?,status?,subregion?,subregionCode?,isPrimary?,evidenceIds?,reviewStatus?}`. PATCH `/facilities/:id` accepts any nonempty subset except immutable accountId. Country is required on create. New facilities default `needs_review`. Reviewed facilities require same-account reviewed evidence. Selecting a primary facility clears any previous primary selection atomically and retains its history. Changing geographic fields requires explicit factual reacceptance. Opportunity country is synchronized for linked facility ids.
- GET `/events?accountId=...`: `{items:[event]}`. POST `/events`: `{accountId,title,eventDate?:YYYY-MM-DD|null,facilityId?:id|null,claimType?:'hypothesis'|'source-supported event',evidenceIds?,description?}`. PATCH `/events/:id` accepts a nonempty subset except accountId. Source-supported events require nonempty reviewed evidence. Duplicate account/title/date/facility records return409. Event edits synchronize linked opportunity event title/date. Merged historical events are edited through the controlling event or unmerged first.
- POST `/opportunities`: `{accountId,eventId,title,productId,requirement?,reasoning?,whyNow?,scale?,route?,commercialValue?,valueBasisEvidenceIds?,facilityId?,facilityCountry?,evidenceIds?,contradictionIds?,contextIds?,dimensions?,unknowns?,confirm?,weaken?,disprove?,barriers?,type?,reviewStatus?,analystStatus?}`. PATCH `/opportunities/:id` accepts a nonempty subset except accountId. `productId` must match the HP catalog; an explicitly excluded record uses `{productId:null,productFamily:'description',outOfScope:true}` and receives zero product-fit points. Product family defaults to the chosen catalog id. Dimensions are nullable integer values0–4. The new record starts with unknown dimensions, no procurement claim, unverified supply route and unquantified value. A quantified commercial value needs reviewed source evidence. Evidence must belong to the account, new supporting sources must be reviewed and controlling, and the same document cannot simultaneously support/contradict/be context. Existing historical links remain inspectable. Account/event/facility attribution must agree. A reviewed opportunity needs supporting evidence.
- POST `/opportunities/:id/buyers`: `{role,scope?,organization?,person?,status?,evidenceIds?,authority?,authorityStatus?,verificationAction?,sourceUrl?,verifiedAt?}`. PATCH `/buyers/:id` accepts any nonempty subset. Defaults to an unresolved role with purchasing authority unverified. Any named or verified person needs reviewed same-account controlling evidence containing that exact name. Source URL must match the evidence and is otherwise derived. Published role verification does not itself verify purchasing authority. No future verification timestamps.
- POST `/opportunities/:id/actions`: `{title,phase?,outcome?,role?,question?,progressCondition?,stopCondition?,status?,description?,dueDate?}`. PATCH `/actions/:id` accepts any nonempty subset. Status is pending/in_progress/done/stopped. A complete default qualification question, owner target, advance/stop condition is retained if a newly created row has only a title. No outreach is sent.
- POST `/opportunities/:id/procurement`: `{explicit,status,deadline,verifiedAt,noticeId,evidenceIds,verificationBasis,amendment?,supersedingEvidenceId?}`. Status is unknown/open/closed/canceled/awarded/superseded; deadline is null, a date (end of that UTC day), or a zoned ISO timestamp; verifiedAt is a zoned ISO timestamp. Explicit evidence requires reviewed same-account procurement/contract-award sources. Open notices additionally require a notice id and future deadline. Changed deadlines need an amendment explanation and reviewed evidence. Superseded status needs the reviewed replacement document and amendment explanation. Prior notice states remain in `procurement.history`; original source documents and versions remain intact. Source verification is the analyst's dated assertion, not an automatic external confirmation.

`reviewStatus` permits needs_review/reviewed/rejected. Unreviewed authored locations do not establish territory eligibility. Account, event and buyer ids cannot be moved across accounts.

Compatibility aliases normalize to display fields: opportunity requirements→requirement, hypothesis→reasoning, commercialRoute→route, valueStatus→commercialValue; buyer name→person; action window→phase, owner→role, source→question, stopIf→stopCondition. Prefer the canonical fields above.

Event reconciliation and source relationship endpoints are described in [audit-api.md](audit-api.md).
